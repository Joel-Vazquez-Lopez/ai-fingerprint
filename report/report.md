# AI Fingerprinting Classifier: Embedding-Based Source Classification

**Author:** Joel Vazquez  
**Repository:** https://github.com/Joel-Vazquez-Lopez/ai-fingerprint  
**Hugging Face demo:** https://huggingface.co/spaces/Jovaz/ai-fingerprinting-classifier  
**Hugging Face dataset:** https://huggingface.co/datasets/Jovaz/ai-fingerprinting-dataset  

## 1. Introduction

This project investigates whether short writing samples can be classified according to their source. The main task is to distinguish between human-written text, human text polished with AI, and responses generated by several AI systems. The broader motivation is that AI-generated text is increasingly common, but authorship and source attribution remain difficult to evaluate reliably. Instead of treating the system as a definitive detector, this project frames classification as a probabilistic writing-style signal.

The project includes two related classification settings. The first is a seven-class source classifier with the labels `human_original`, `human_ai_polished`, `chatgpt`, `claude`, `deepseek`, `gemini`, and `grok`. This is the main embedding-based classifier. The second is an AI-only attribution experiment that compares only AI model labels. This extension helps test whether different AI systems leave distinguishable writing patterns.

## 2. Dataset

The dataset was custom-built from prompts answered by several sources. It includes responses from ChatGPT, Claude, Gemini, Grok, and DeepSeek, together with human-written answers and human-written answers polished with AI. The processed files are split into training and test sets, stored under `data/processed/`.

The project also includes an expanded AI-only dataset for model attribution. This second dataset focuses on distinguishing between AI systems rather than separating human and AI text. Creating both datasets made it possible to compare a broad authorship task with a narrower AI-model attribution task.

## 3. Embeddings And Classifiers

The main classifier uses sentence embeddings from `sentence-transformers/all-MiniLM-L6-v2`. These embeddings represent each text as a dense semantic vector. Several classifiers were trained and evaluated, including Logistic Regression, Linear SVM, Random Forest, and MLP. The best model for the seven-class task was the MLP classifier.

For comparison, the project also trained an AI-only character n-gram TF-IDF model with Linear SVM. This model does not use sentence embeddings, but it performed strongly for AI attribution because it captures local stylistic signals such as punctuation, formatting, repeated phrase patterns, and small lexical habits.

## 4. Results

The seven-class embedding-based source classifier achieved 50.71% accuracy and 50.54% macro F1, compared with a 14.29% random baseline. This shows that the embeddings contain meaningful signal for distinguishing between human, AI-polished, and AI-generated text, although the task remains difficult.

For the AI-only attribution task, the best embedding-based classifier achieved 47.50% accuracy and 47.30% macro F1 across five AI systems, compared with a 20% random baseline. This suggests that sentence embeddings capture some model-specific signal, but not enough for highly reliable attribution.

The strongest overall result came from the AI-only character n-gram TF-IDF model with Linear SVM, which achieved 84.50% accuracy and 84.40% macro F1. This indicates that AI model attribution may depend more on surface-level writing fingerprints than on semantic meaning alone.

## 5. Demo System

The project includes a web demo hosted on Hugging Face. The interface lets users paste text, choose the classifier system, and view the predicted source with probability scores. The demo also includes sample inputs and links to the official AI systems represented in the dataset. This makes the project easier to test and interpret without running the code locally.

## 6. Reflection On AI Tools

AI coding tools were useful for building scripts, improving the demo interface, drafting documentation, and iterating on model-training workflows. They helped accelerate development, especially when connecting the dataset, models, and web app. However, the work still required manual checking. AI tools can hallucinate file paths, overstate model performance, or produce explanations that sound more certain than the results justify.

The most important human decisions were defining the labels, checking the dataset structure, comparing models, and writing limitations clearly. This project reinforced that AI tools are useful for speed, but the developer still needs to understand the data, verify outputs, and explain uncertainty responsibly.

## 7. Limitations And Future Work

The classifier should not be interpreted as proof of authorship. It learns patterns from the collected dataset and may fail on very short texts, translated texts, heavily edited writing, future model versions, or models not included in training. The predictions should be treated as signals rather than definitive evidence.

Future work could expand the dataset, include more AI systems, collect more human writing samples, evaluate robustness across prompt types, and test whether combining embeddings with character-level features improves performance.
